# Public evaluation artifacts

## Week 2: retrieval, not answer accuracy

`../data/golden_questions.json` contains 20 questions with `evaluation_scope: rag_only`, `rag_answerable`, expected facts and expected Studio guide IDs. Sixteen positives determine macro guide recall@5; four negatives test corpus limits and are excluded from the recall denominator. A negative does not prescribe a full-agent refusal. The revised automation question does not assume one shortcut/command per mode.

`studio_retrieval.json` retains the actual Phase 5A read-only Pinecone measurements: A/B/C all **1.000** guide recall@5. `phase5a_baseline/` preserves the previous dataset/results; the 16 positive questions/source judgments are unchanged. One negative's wording changed, so aggregate latency and that negative's retrieval are not a controlled comparison. This small author-designed set does not measure answer accuracy, passage precision or negative-answer detection.

Reproduce live retrieval **only when cloud query use is intended**, from backend: `uv run python -m app.rag.studio_cli evaluate`. It does not upsert records, call the answer model or run web searches. The saved score is historical; cleanup did not requery Pinecone.

## Week 3: agent policy versus live answer quality

`../data/agent_golden_questions.json` contains 12 rubrics spanning conceptual answers, official procedures, creative advice, diagnosis, discovery, licensing and insufficient evidence. It distinguishes known support, research candidates and conditional post-research insufficiency. It does not hardcode model wording.

Offline commands from backend:

```sh
uv run --offline python scripts/evaluate_agent.py
uv run --offline python scripts/evaluate_agent_golden.py
```

The first executes ten real-graph scenarios with synthetic scripted provider responses. The second executes linked policy regressions for 12 golden scenarios; it does **not** replay each exact golden conversation or measure live factual quality. Their current reports are regenerated by these offline checks. For a future live run, retain actual tool/evidence records privately and score tool/context choice, source applicability, supported claims, completeness/partial usefulness and clarity/progression, 0–2 each. Mark unassessed dimensions explicitly; invented essential UI instructions or licensing permissions fail groundedness.

`verified_source_inventory.json` retains original source URLs and the names of historical evidence artifacts, not their third-party excerpts. Raw traces and verbose model outputs were archived privately before removal. They were not silently converted into independent verification. No fresh source-availability check was performed during cleanup.

## Reproducible preparation

`studio_preparation.json` is the local original-guide build result: 12 guides, 4,640 words, A/B/C **36/24/12**. The preparation pipeline no longer reads private manual chunks. The offline reproducibility test uses an isolated tree with only the original guide directory, asserts stable outputs and unchanged guide content, and compares existing generated chunks when available. This is not a new plagiarism or independent technical-accuracy audit.

Historical manual preprocessing results were **375/232/168**; these are different datasets, not current production chunk counts. See [historical results](historical_results.md). Private raw manuals/processed outputs are not required for the public Studio pipeline.
